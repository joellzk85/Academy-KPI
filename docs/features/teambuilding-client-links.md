# Teambuilding proposals and client link tracking

Moved from CLAUDE.md on 2026-10-21. Detailed history of what was built and agreed. Read only when working on this area.

- **Teambuilding proposal, push A1 (built 2026-10-19; Joel's Texas Chicken "Leading Beyond Expectations" Canva proposal as the model).** Joel: "it should look like a standalone website, custom made for customers", "all compartments editable", "everyone can amend", and it must **not affect course outlines** (it doesn't: separate list, separate screens; the outline code is unchanged).
  - **Where:** its own workspace menu item **"Teambuilding proposal"** right under Course outlines (Joel chose the name; Course outlines keeps its name and works as before). Three tabs: **Proposals · Activity library · Package template**. On a New deal, Next step has **Create / Open teambuilding proposal** next to Create course outline; Documents lists "Teambuilding proposals". My home has a "Teambuilding proposal" shortcut. **Repeat this deal** is unchanged (it skips the proposal).
  - **Who:** everyone builds them, with the same rights as outlines (own, shared with, Admin and Management edit any). **Everyone** can add and edit activities and the package template (delete an activity: the person who added it or Management; anyone can "Stop using" it).
  - **The website** (`TeambuildingSite.tsx`, NEXT look: Poppins, teal `#50a88b`, chevron `#5bc09f`, mint `#b6dccf`): a full-screen cover (photo with the title over it, "Prepared for <client>", date, length, group size), a bar that stays at the top with links to each section, then sections that fade in as they scroll: **Objectives**, **Our trainers** (photo, name, title, bio), **Agenda** (day tabs, time, item, Indoor/Outdoor/Dining tag), **Featured activities** (photos, duration, location, format, group size, the 5 bars Collaboration/Creativity/Problem solving/Intensity/Difficulty, learning objectives and takeaways, folding "How it is played", "Expected deliverables", "Materials"), **Recommended venues** (Option 1, 2…: photos, stay, travel distance and time, notes), **Packages** (group-size box with + and −, package cards with total and price per person, the comparison table; on phones the chosen package's list), **Key takeaways and next steps**, **HRD Corp claimable** (only on HRDC deals; standard note, editable), **Terms** (the course-outline standard terms by default, editable), and a teal footer with the company details, the deal owner's name and "Private & Confidential". Each section can be switched off, moved and renamed per proposal ("Sections → Arrange"); an empty section isn't shown.
  - **One source of truth:** client and contact from the deal's client; date (unless typed) and group size (unless changed) from the deal; trainer name and photo from the trainer list (bio from the list unless "Tailor for this client"); venue name and photos from the venue list (distance and travel time typed per proposal, as they depend on the client); activities copied from the library and then tailored ("Use the library's latest version" to refresh; a typed one can "Also save to the Activity library"); packages start from the Package template. Sending writes everything into a locked copy; Revise reads live again.
  - **Price bands (Joel: "the number of pax should be flexible, it directly affects the costing"):** each package has a price for the whole group per band (e.g. 20-30 pax RM 21,000, 31-50 RM 30,000), and a band can change table cells (e.g. 6 facilitators instead of 4). Fewer than the smallest band: the smallest band's price ("Minimum N participants"). More than the biggest: "Contact us". Logic `priceFor`/`cellFor` in `lib/teambuilding.ts`. The rep changes the group size in the editor (or Preview); the client changing it on the page comes with the live link (push B).
  - **Photos:** trainers have `photoUrl`, venues `photos[]` (first = main; the old `pictures` link still shows), plus the cover photo and activity photos. Uploaded through `PhotoPicker` (made smaller in the browser first: longest side 1600px, JPEG) to `photos/{folder}/{id}.jpg`; the download link is saved. Photo files are never deleted from the CRM, so a sent proposal never loses a picture.
    - **Screenshots (2026-10-19, Joel: "make it easy to drop screenshots or screen cuts"):** every photo box (proposal cover, trainers, venues, activities, and the Trainers and Venues pages) also takes a **dropped** file (the box turns teal with "Drop here"), **Ctrl+V** anywhere on the page (goes to the box last pointed at, clicked or tabbed into; pasting into a text box is left alone when the clipboard also has text) and a **Paste screenshot** button (reads the clipboard; the browser may ask once; if refused it says to press Ctrl+V). Any image the browser can read (JPG, PNG, WebP, GIF, BMP) is accepted; it's still turned into a JPEG before upload, so `storage.rules` didn't change. A picture dragged straight from a web page gets a plain message to save or copy it first. Tested with a temporary local page (fake uploads): paste, drop of two files, the photo limit, a single photo being replaced, a locked box, a wrong file, phone width.
  - **Preview** is full screen and shows exactly the website, with a **Computer / Phone** switch (the phone view is a real phone-width frame, so it uses the phone layout).
  - **Send:** the same Send window as outlines (`TeambuildingSendDialog` in `QuoteSendDialog.tsx`; Email with the PDF, WhatsApp, Download PDF + Mark as sent). It locks the proposal, logs `sendLog`, and moves a New deal to Proposal sent with History "Proposal sent: teambuilding proposal TB/…" (same programme/value check via `GapsBox`, same "only owner, Admin or Management move the deal" rule). `/api/mail/send` accepts `tbProposalId`. References are `TB/YYYYMMDD/NN`. Push B will make "Send link" the default.
  - **PDF** (`lib/tbPdf.ts`): a printout of the website drawn in a hidden computer-width frame (same look whether made on a phone or computer): a full-page cover, then sections one after another on A4 pages, cut between cards, with the client's company name as a faint diagonal watermark on every page. About 1.5 to 2 MB with photos. Photos reach the PDF through the server (`/api/photos/get`, logged-in members, our `photos/` folder only) because Firebase Storage doesn't let the browser use them in a picture.
  - **Also:** "Shared with me" alerts work for teambuilding proposals (menu count, list, My home card); deleting a deal hides its draft teambuilding proposals and Management → Lost and deleted → Restore brings them back; the backup has "Teambuilding proposals", "Teambuilding activities" and "Teambuilding settings" tabs; screens filter with `linkedOnly`.
  - **Rules need publishing:** `firestore.rules` (`teambuilding_proposals` like outlines; `tb_activities` members read/add/edit, delete by the adder or Management; `tb_settings` members) and `storage.rules` (`photos/{folder}/...`: members read and upload JPG/PNG/WebP up to 10 MB as themselves; never changed or deleted).
  - Tested with a temporary local page (the real workspace on a fake in-memory database with a copy of the new rules), as rep, Admin and Management, desktop and phone: building from a deal (trainers, library activities, venue), the website section by section on computer and phone (no sideways scroll), group size below, inside and above the bands, the shared alert, the Activity library with a photo upload, the Package template, the trainer photo, the Send window by email (missing-details box first, deal moved, back to the deal), Mark as sent and Revise, deleting a deal, rights (a rep can't change someone else's unshared proposal or delete someone else's activity), and the PDF (9 pages, watermark). **Live site only:** real photo uploads (Storage must be on), photos in the PDF (server route), real Outlook sending.
  - **External trainers (A2, agreed, not built):** a private link per proposal for an outside trainer to build it: no login, no download, no prices; the team accepts.
- **Teambuilding proposal links, push B (built 2026-10-19; Joel's spec, decisions: one link per proposal for everyone, teambuilding only for now, course outlines later; "Reps can see proposal tracking" starts Off).**
  - **Built on the client links the other chat made for quotations and outlines** (`doc_links`, `DocLinkBox`, `serverDocLinks.ts`): a teambuilding link is a `doc_links` record with `kind: 'teambuilding'`, opened at **`/p/<token>`** (32 random hex characters). Extra fields: `expiresAt` (end of the chosen day, Malaysia time), `extendedAt/ByName`, `ownerId` (deal owner), `totalSeconds`, `accepted` ({name, position, note, packageName, pax, price, at}). `/api/doc-link/create` needs `expires` for teambuilding (today to 180 days ahead, `expiryProblem`), `/api/doc-link/extend` is new, `/api/doc-link/stop` is "Revoke link". `/api/doc-link/get` refuses teambuilding links (they have their own page).
  - **Send window (teambuilding):** only **Client link** and **Download PDF** (+ Mark as sent). Client link: expiry picker (7 / 14 / 30 days or a date; `ExpiryPicker`), **Make the client link** (locks the proposal, logs `channel: 'link'`, moves a New deal to Proposal sent like any send), then Copy link / Copy message with link / Open (`?team=1`, not counted) / **Extend** / **Revoke link**, "Works until … (N days left)" (amber within 3 days, red when expired), and "Accepted online by …". One link per proposal: making it again gives the same link. The editor has a **Client link** card with the same box. **Unlike quotation links, it shows the latest saved version** (Joel: a fix after Revise + Save appears on the same link).
  - **The client's page** (`ProposalLinkPage.tsx`, `main.tsx` routes `/p/`): no login; talks only to `/api/proposal-link/get | visit | accept` (`serverProposalLinks.ts`), which return only what the website shows (`publicProposal`; no ids, sharing, logs or other CRM data). The website (`TeambuildingSite` mode `client`), the client can change the group size and switch packages, then **Accept proposal** (name, position, optional note; shows the chosen package, pax and band price). Accept: a deal at New or Proposal sent moves to **Client approved** (`stage: 'agreed'`, `agreedDate`, `proposalAcceptedAt`) with History "Client accepted the proposal online: <name>, <position> (package, pax, RM …)"; further along it's only recorded; never Won; a second accept is refused. Expired or revoked: a polite page with the rep's name and the company phone/email (the team has no phone numbers in the CRM).
  - **Protection:** no download button; printing shows only a blank "Private & Confidential" page (print CSS); right-click, copy/cut, text selection and image dragging blocked; Ctrl+P / Ctrl+S blocked; a faint repeating watermark of the client's company name and today's date. The page never says it's tracked. (A phone screenshot or a photo of the screen can't be stopped.)
  - **Tracking** (`proposal_views/{visitId}`, written only by the server, **no IP addresses**): device (phone/tablet/computer) and browser, seconds per section (the section in the middle of the screen, counted only while the tab is visible; sent about every 15 seconds and with `sendBeacon` when the tab hides/closes; the server accepts at most 2 minutes per update and only known sections), and events labelled **possible**: screenshot (Print Screen, Win+Shift+S, Cmd+Shift+3/4/5, focus lost right after a Win/Cmd shortcut), print (Ctrl+P, print menu), copy, right-click. The same kind within 3 seconds is one attempt. Not tracked: the CRM's Open button (`?team=1`), a browser where someone is logged in to the CRM (Firebase login found in IndexedDB), and Preview. Views and first-open History as quotation links; one History line per visit for possible screenshot/print/copy attempts.
  - **In the CRM:** deal panel **Proposal link** section (`ProposalTracking.tsx`): link box, then for people allowed: "Viewed N times, last opened … , total time", time-per-section bars, visits (date, device, browser, duration, possible attempts), the list of possible attempts. Deal History (server). Client timeline: "Client opened the teambuilding proposal …" **dashed, not a touch point** (`kind: 'proposal_open'` in `lib/touchPoints.ts`). My home card **Proposal activity** (`ProposalActivity.tsx`): accepted online (14 days), opened today, sent but not opened after 3 days, expiring within 3 days; reps their own deals, Admin all, Management all with a rep picker; in everyone's default cards and added once at the top for saved layouts (`user_prefs.proposalCardAdded`, after the other one-time cards). **Red dot** for the deal owner (deal row text + Deals menu): "Client opened the proposal (again)" or "Proposal accepted online", cleared when the owner opens the deal (`user_prefs.proposalSeen[token] = {views, accepted}`, `useProposalAlerts`). My follow-ups' "opened your …" line includes teambuilding.
  - **Who sees tracking (replaced on 2026-10-20 by "Client link tracking" below: Management only, plus people Management ticks, on their own deals):** Management → Follow-up rules → **Proposal tracking** → "Reps can see proposal tracking" (`config/proposal_settings.repsSeeTracking`, Management only, default Off). Off: reps see only whether the link is live, its expiry and whether it was accepted (no opens, visits, red dot for opens, timeline entry or "opened/not opened" on the card). Admin and Management always see it. The **database rule** for `proposal_views` enforces it (reps read only when the setting is on). The open count on `doc_links` is readable by members, as for quotation links; the screens hide it from reps while Off.
  - **Rules need publishing:** `firestore.rules` (`proposal_views`, `proposal_settings` added to the Management-only config docs). The backup has "Client links" and "Proposal visits" tabs.
  - **Tested:** the real server routes against a fake database with a script (27 checks: expiry required and validated, one link per proposal, the quotation page refusing it, team opens not counted, no CRM fields to the client, live version, visit sections/events, one History line per visit, no IP, team visits skipped, accept validation, band price, deal to Client approved, second accept refused, further-along deals only recorded, expired/revoked polite page with contact, Extend, Revoke, made-up link refused). Screens with a temporary local page on a fake database: the client page on a phone (watermark, blocked copy/right-click/Ctrl+P, tracking captured incl. the close beacon, Accept with the chosen package and pax, thank-you, expired page), the Send window (expiry picker, make link, lock, deal moved), deal panel as rep with the switch off and as Management (tracking, Extend), the switch (and a rep refused), red dot on and cleared, "again" and "accepted" alerts, the Proposal activity card (rep, Management, switch off), the client timeline (dashed), the Preview's inactive Accept. **Live site only:** the real link from a phone, the close-of-tab beacon to the server, real screenshot keys, the IndexedDB team check.

- **Client link tracking and protection (built 2026-10-20; Joel: "proposals and quotations to client should be tracking: heatmap, open duration, touch point, view duration, mouse scroll over and stay duration, suggest me more"; then "client cannot download or screenshot", "do not tell customer we are tracking", "only management can see tracking", "management can approve which rep to see"; "touch point" = where the client clicked or tapped, not a client-history touch point, so reps can't infer tracking from the colour dot):**
  - **Every client link** (quotation /q, course outline /o, teambuilding /p) now has the same protection and tracking. Nothing on the page mentions either.
  - **Protection** (`LinkGuard.tsx`): quotation and outline links lost their **Download PDF** and **Print** buttons (the team still downloads PDFs in the CRM and can send one by hand). Printing gives a blank "Private & Confidential" page; right-click, copy, cut, text selection and dragging pictures are blocked; Ctrl+P and Ctrl+S are blocked; a faint watermark of the client's company and today's date covers the screen; on a computer the page **blurs** while the window has no focus (Snipping Tool, switching programs) or the Windows / Cmd / Print Screen key is down, and clears on return. A phone's screenshot buttons or a photo of the screen can't be stopped by any website; the watermark is for that.
  - **Tracking** (`lib/linkTracker.ts`, once a second while visible; sent every 15 seconds and with `sendBeacon` when hidden or closed, to `/api/link-visit`): visible and **active** time (activity in the last 30 seconds; the rest is "idle"), seconds per part (the part at the screen's middle), the **reading heatmap** (each of 20 bands per part gets a second while in the middle 70% of the screen), **mouse rest** (part × 20 rows × 10 columns, computers, mouse moved in the last 5 seconds), **clicks and taps** (where, left button only), read **depth**, a random **device id** kept in that browser (`next_dev`, so several = possibly forwarded), teambuilding **packages and group sizes tried** (the automatic first package isn't counted; a group size counts once it stays 1.5 seconds), and possible screenshot / print / copy / **download (Ctrl+S, dragging a picture)** / right-click attempts. Parts are marked `data-track`: quotations `letterhead, client, details, items, total, remarks, terms, sign` (`QuotationDocument`; the table now has two `tbody`s, same look), outlines one per page (`cover`, `overview`, `modules-1`…; `CourseOutlineDocument`), teambuilding the section keys. Team opens (`?team=1` or a browser logged in to the CRM, `teamBrowser`) send nothing.
  - **Server** (`serverLinkVisits.ts`): `/api/link-visit` (public, 120 a minute per address; `/api/proposal-link/visit` kept for teambuilding tabs opened before) checks the link is open and cleans everything (`cleanVisitUpdate` per kind; no number above 2 minutes per update; caps on map sizes), then merges into `proposal_views/{visitId}` (`mergeVisit`) with `kind`, `ownerId` (deal owner, else link maker), `deviceId`, `active`, `heat`, `hover`, `taps`, `depth`, `picks`, `open`. No IP addresses. `/api/link-preview` (logged in, tracking allowed) returns the document as the client saw it, for the heatmap, whatever the link's state. **No more "Client opened…" or "possible screenshot attempt" lines in deal History** (History is seen by everyone on the deal); accept and reopen-request lines stay.
  - **Who sees it:** Management always. Management → Follow-up rules → **Client link tracking** ticks other people (`config/proposal_settings.allowedIds`; the old `repsSeeTracking` is ignored), who then see it **only on their own deals** (`trackingAccess` / `seesLink` in `lib/proposalTracking.ts`). Admin no longer sees it unless ticked. Everyone else sees only whether a link is live, its limits, reopen requests and online accepts. Applies to: the open counts in `DocLinkBox` (it now takes `viewer`), the deal panel, the red dot "Client opened the … (again)", My follow-ups' "Opened your …" line, the client timeline's dashed "Client opened …" line (now every link kind), and Client link activity. The **rule** for `proposal_views` enforces it (ticked people must query with `ownerId ==` themselves). Admin's Excel backup download leaves out "Client link visits" (the daily Google Sheet copy still has every list). The open count on `doc_links` stays readable by members in the database (needed for limits); the screens hide it.
  - **What Management sees** (`LinkUsage` in `ProposalTracking.tsx`): **Reading now** (a visit updated in the last 45 seconds and not closed), **Hot / Warm / Cold** (`scoreOf`: opens, active minutes, several devices, recency, read to the end, price focus; Hot 60+, Warm 30+), viewed N times, open time split into reading and idle, "Possibly forwarded: opened on N devices or browsers", "Read to the end" or "Got N% of the way down, last part reached: …", "Spent most of the time on pricing" (price parts ≥ 40% and ≥ 20 seconds: quotation lines and total, teambuilding packages), packages tried, time on each part, visits (device, reading time, depth, Reading now), attempts, and **Show heatmap**.
  - **Heatmap** (`LinkHeatmap.tsx`, loaded only when opened): the document from `/api/link-preview` with one layer: **Reading** (orange, light = little time, dark = a lot), **Mouse**, or **Clicks and taps** (dark dots = clicks, purple = taps); all visits or one; teambuilding at **Computer** or **Phone** width (layouts differ). Point at a colour for the seconds. Positions are re-measured every second from the `data-track` parts, so they follow the layout.
  - **Where:** the deal panel's **Client links** section (was "Proposal link"; now every link on the deal); Management → **Client links** ("Reading now" and "Hot links" tiles, badges on each row, the full tracking and heatmap in each row's details); My home card **Client link activity** (was "Proposal activity"; every link kind; adds Reading now and Hot for people who see tracking).
  - **Rules need publishing:** `firestore.rules` (`proposal_views`).
  - Tested with a script (29 checks: cleaning per kind, caps, older pages, merging, summaries, Hot score, read depth, price focus, who sees what) and a temporary local page with a pretend server: the quotation link (no buttons, watermark, blur cover until clicked, Ctrl+P / Ctrl+S / right-click recorded and blocked, the stored visit), Management's panel and the three heatmap layers (mouse rest and clicks where they were made), phone width (no sideways scroll), and the teambuilding link (sections marked, package and group-size tries). **Live site only:** real visits reaching the server, the database rule, the heatmap's document from `/api/link-preview`, a real phone, the Snipping Tool.


## Client logo on teambuilding proposals (2026-10-21)

- The logo lives only on the client (`clients.logoUrl`, Clients → Edit → Company logo; `uploadPhoto` folder `logos`, PNG keeps its see-through background, up to 600px). The proposal reads it live (`resolveTb` → `clientLogo`); nothing is copied. Shows in the site's top bar (computer and tablet), as a "NEXT × client" badge on the cover and on the PDF cover. Per proposal: **Show client logo on the cover** (`hideClientLogo`, on by default). The `/p/` server route sends `clientLogo` only when shown. **Publish `storage.rules`** (`photos/logos`).
- **Download PDF: Vertical or Horizontal (built 2026-10-23; Joel's JM Bariani PowerPoint as the model).** Download PDF (editor bar and Preview) opens a choice: **Vertical (A4)** is the website printed page by page, as before; **Horizontal (slides)** is a widescreen 16:9 deck (`TeambuildingSlides.tsx`, drawn by `tbPdf.ts`): cover (photo left; title, date / stay / pax pills, NEXT logo, HRDC badges on HRDC deals), objectives, one slide per trainer, agenda one slide per day (long days split), one slide per activity plus a "details" slide when it has objectives / takeaways / how played / materials, a venue table then one slide per venue, packages and the "What's included" table, takeaways, HRDC, terms (two columns, split), and a Thank you slide. The client's name is watermarked on every page; a slide that runs too long is shrunk to fit. Sending still attaches the Vertical PDF. "Corporate clientele" from the sample is not included (no client-logo list in the CRM yet). On 2026-10-23 Joel said the download was failing; both PDFs downloaded fine on a test proposal, so the cause on the live site is still open (ask for the red message). No database rules change.
