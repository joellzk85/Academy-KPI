## How it works
- **Where:** `/trainer` on the live site (`src/main.tsx` → `TrainerPortal.tsx`). The portal uses its own Firebase connection (named app `trainer-portal`), so a team member logged in to the CRM in the same browser stays logged in.
- **Logins:** a Firebase Auth user with id `tr_<trainerId>`, made by the server. It has no `auth_map` record, so the database rules give it nothing; the portal only talks to `serverTrainerPortal.ts` (`/api/portal/*`), which checks the login and returns only that trainer's own things. Uploads go straight to Storage `trainer_portal/{trainerId}/…` (`storage.rules`: only that trainer, while `trainer_accounts/{trainerId}.active`).
- **Giving access:** Trainers → open a trainer → **Trainer portal** box (Admin and Management): type the email → **Give portal access** → the server makes or updates the login and `trainer_accounts/{trainerId}` → the browser asks Firebase to email the "choose your password" link → Copy message / WhatsApp with the portal address. Also **Send password email again**, **Change login email**, **Turn off access** (disables the login and logs them out). The list shows a small "Portal" tag. Profile links and outline links are unchanged and still work for every trainer.
- **The portal:** Home (to-do list: accept a PO, request a fee, add bank details / TIN; next training; average rating; profile %), **My trainings** (upcoming and history: programme, client, dates, venue, Confirmed / Being arranged, PO download and **Accept the PO**, fee lines with status, the fee request, rating), **My profile** (the same form as the profile link, `TrainerProfileFields.tsx`, with Preview HRDC biodata; saves straight to `trainers_directory`, IC to `trainer_private`), **Payment details** (bank, TIN, address). "Change my password" sends the reset email.
- **Which trainings:** won deals (not deleted, owner on the Team list) whose checklist **Trainer step** has this trainer picked (`trainerId`). A trainer only on the quotation doesn't see it until Admin picks them on the checklist.
- **PO:** the file(s) uploaded on the Trainer step. The server streams them (`/api/portal/po`). **Accept the PO** sets `trainer_jobs.poAcceptedAt` and adds a deal History line.
- **Request training fee:** from the training's start date. Photos (made smaller to JPG) and the T3 (PDF, JPG or PNG) → `/api/portal/claim` → `trainer_jobs.claim` (`submitted`) and a deal History line. The fee lines are not changed (one home for the request: `trainer_jobs`). Training report: "coming soon" placeholder. The trainer can change and resend until every fee line is paid.
- **Alerts:** a red flag on the deal in Admin work's work queue (`claimFlag`: "X asked for their fee: check the photos and T3, then approve", or "…there's no trainer fee line yet: add it on the Trainer step"), gone once every fee line is approved or paid; and **Trainers asking for their fee** at the top of Admin work → Money.
- **Deal's Trainer step** (`TrainerJobBox`): PO accepted date, the fee request with photo thumbnails and T3 links, **Ask the trainer to fix something** (note shown in the portal; status `returned`), and the **rating** (1 to 5 stars + comments; Admin and Management set it, everyone sees it). Trainers panel shows the average and each training's rating.
- **Bank changes:** `trainer_bank_requests/{trainerId}` → **Bank accounts from trainers, to check** on Trainers and Admin work → Money → Accept (writes the trainer's vendor record, creating one if needed) or Reject (reason shown in the portal). Typing back the account already on record cancels a pending change.
- **TIN:** new `tin` field on the vendor record (also in Admin work → Vendors' form). Saved from the portal straight away (a vendor record is created for the trainer if none).

## Records
- `trainer_accounts/{trainerId}`: email, active, created/updated, lastSeenAt, history. Members read; only the server writes.
- `trainer_jobs/{dealId}_{trainerId}`: rating, poAcceptedAt, claim. Members read; Admin and Management write (the server too).
- `trainer_bank_requests/{trainerId}`: Admin and Management read, accept, reject; only the server creates.
- Code: `src/lib/trainerPortal.ts` (records, cleaning, flag), `src/lib/portalEmail.ts`, `serverTrainerPortal.ts`, `src/components/TrainerPortal.tsx`, `TrainerPortalAdmin.tsx`, `TrainerProfileFields.tsx`.

## PO as PDF and the single-source check (2026-10-21; Joel: "trainer can download their PO - PDF"; "double check all links, no duplication")
- **Make PO (PDF)** on the deal's Trainer step, under the PO files (Admin and Management; `TrainerPoDocument.tsx`): a NEXT Academy purchase order built from the deal (programme, client, dates, venue), the trainer (name, address, phone, email), the fee lines on the Trainer step (not rejected) and the trainer's bank on record. PO number `PO-<training yyyymm>-<last 5 of deal id>` (same for a training every time). Saved as the step's PO file (`checklist_files`, via `uploadOne`), so the step can be ticked and the trainer downloads it as a PDF in the portal. Needs the trainer picked from the list and at least one fee line. Uploading your own PO file still works.
- **Single source, checked:** PO = the Trainer step's files only (CRM, Overview and portal read the same records). Portal profile = `trainers_directory`; bank and TIN = the trainer's vendor record (also what the payment summary uses); trainings = deal + checklist; ratings, PO accepted and fee request = `trainer_jobs` (one per trainer per training; resending replaces it).
- **Fixes:** the fee request no longer writes `trainerClaimAt` onto the fee lines (the date lives only on the request); Admin work → Money's "Trainers asking for their fee" finds fee lines by the Trainer step like the rest; adding a cost line for a vendor who already has one on that step asks first ("add another anyway, e.g. a balance payment?") so the same fee isn't paid twice by mistake; the trainer panel says its "Upcoming trainings" include quotation-only deals while the portal shows only won deals with the trainer picked on the checklist.

## PO made automatically, accept or decline, blocked dates, own calendar (2026-10-21; Joel: "PO for trainer should auto generate and block trainer in trainer portal - trainer can choose to link to their own calendar"; "trainer can reject - it notifies in Admin work"; dates blocked only for won deals with the trainer picked)
- **PO made automatically:** a won deal with the trainer picked from the list on the Trainer step and at least one fee line (not rejected) has its PO, nothing to click (`buildPo`, `hasAutoPo` in `src/lib/trainerPortal.ts`). The server sends it to the portal as `poAuto`; the trainer's browser makes the PDF (`TrainerPoDocument`). Uploaded PO files on the step still win when there are any. **Accept** keeps a copy on `trainer_jobs.po` (it doesn't change if the fee changes later); the Trainer step shows **Fee changed? Send a new PO** (clears the acceptance). "Make PO (PDF)" stays, optional (a saved copy, e.g. for a trainer without the portal). The Trainer step can be ticked with the automatic PO (gate: fee line or uploaded PO).
- **Decline:** the trainer can decline before the training starts (also after accepting), with a reason (`/api/portal/decline-po` → `trainer_jobs.poDeclined`, deal History line). Red flag in Admin work's work queue ("X declined the PO ("reason"): pick another trainer on the Trainer step") and on the Trainer step, and **po-declined** (red, first) in Trainers → Overview. Gone when another trainer is picked, or Admin/Management click **They agreed after all: clear this**. Accepting again also clears it.
- **Blocked dates:** every training on the trainer's list blocks its dates, except a declined one. Portal **My calendar** tab: month view (teal = confirmed, amber = being arranged) and the list for that month. In the CRM, the Trainer step warns (amber) when the picked trainer is already booked on overlapping dates on another won deal (`TrainerClash`, `clashesWith`).
- **Link to my calendar:** in My calendar. Makes a private address `/api/portal/calendar/<token>.ics` (`trainer_calendars/{token}` = trainerId, server only; no rules needed, the database refuses browsers by default). Buttons: Add to Google Calendar, Add to Outlook, Add to Apple / iPhone calendar (webcal), plus the address to copy. **Make a new link** stops the old one. The feed has the blocked trainings as all-day events (programme, client, venue, Confirmed / Being arranged; no money), stops when portal access is turned off, 30 requests a minute per address. Calendar apps re-read it every few hours (Google can take up to a day).
- **Overview:** "No trainer PO" now only when there's no uploaded PO and no fee line.
